## О проекте

Swift Sport Tuning (SST) — информационный сайт для владельцев Suzuki Swift Sport ZC33S. Здесь собраны сведения о прошивках ECU, тюнинг-компонентах, обслуживании и выборе автомобиля.

- **Прошивки** — карточки Stage 1 и Stage 2 с характеристиками и требованиями к конфигурации.
- **Компоненты** — турбины GR30 / GR39, интеркулеры и сцепление.
- **База знаний** — FAQ, самостоятельная прошивка, уровни тюнинга, покупка автомобиля и диагностика.
- **Каталог запчастей** — артикулы с возможностью копирования и PDF-каталог.
- **Интерфейс** — русский и английский языки, светлая и тёмная темы.

> Сайт носит справочный характер: он не оформляет заказы и не принимает платежи. Цены ориентировочные, а расчётная мощность не заменяет измерения конкретного автомобиля. Связь для консультаций — через Telegram.

## Быстрый старт

Понадобятся **Node.js 22 LTS** и **npm**. В текущем CI используется Node.js 20; зависимость `sharp` требует версию не ниже 20.9.0.

```bash
git clone https://github.com/maltcevrg/zc33s.git
cd zc33s
npm ci
npm run dev
```

Откройте **http://localhost:5173/zc33s/**. Если порт занят, Vite выведет другой адрес в терминале.

Отдельный backend, база данных и настройка `.env` для локального запуска не нужны. Контент хранится в репозитории.

### Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Сервер разработки с автоматическим обновлением |
| `npm start` | Альтернативная команда запуска сервера разработки |
| `npm run build` | Production-сборка в `dist/` |
| `npm run preview` | Локальный просмотр готовой сборки |
| `npm run check:anchors` | Проверка якорей оглавления статей на русском и английском |

Для просмотра production-сборки:

```bash
npm run build
npm run preview
```

По умолчанию она доступна по адресу **http://localhost:4173/zc33s/**. `preview` предназначен для локальной проверки, а не для production-хостинга.

## Редактирование контента

### Карточки прошивок и компонентов

Карточки загружаются Vite-плагинами из папок `TuningCards/` и `CustomCards/`. Добавлять их вручную в JSX не требуется.

1. Создайте отдельную папку внутри нужного раздела.
2. Добавьте текстовый файл `card.txt`.
3. Поместите фотографии во вложенную папку `images/`.

```text
CustomCards/
└── Новый компонент/
    ├── card.txt
    └── images/
        ├── 1.jpg
        └── 2.jpg
```

Минимальный пример `card.txt`:

```text
HEADER - Новый компонент

SUMMARY -
Краткое описание назначения и совместимости.

SPECS -
Совместимость — Suzuki Swift Sport ZC33S

ORDER - 3
```

Поля записываются заглавными буквами в формате `ПОЛЕ - значение`. Многострочное значение продолжается до следующего поля. `ORDER` задаёт порядок на витрине: меньшее число — выше; карточки без него идут после упорядоченных, по имени папки.

Изменения текста и изображений автоматически обновляют страницу в режиме разработки. Английские переводы карточек находятся в [`src/i18n/cardTranslations.js`](src/i18n/cardTranslations.js).

**Все поля, примеры и требования к формулировкам:** [документация формата карточек](docs/card-format.md).

При добавлении страницы обновите маршруты в `src/App.jsx`, список `spaRoutes` в `vite.config.js` и SEO-метаданные. Для новой статьи также обновите данные базы знаний и словари RU / EN.

## Проверка изменений

Перед публикацией выполните:

```bash
npm run check:anchors
npm run build
```

Проверка якорей сверяет оглавления статей RU / EN с разделами в HTML. Она не заменяет ручную проверку: откройте изменённые страницы, проверьте оба языка, обе темы, мобильную вёрстку и прямые ссылки.

## Публикация

Сайт размещается на **GitHub Pages**: https://maltcevrg.github.io/zc33s/.

Workflow [`deploy.yml`](.github/workflows/deploy.yml):

1. Запускается при push в `main` и дополнительные ветки, явно перечисленные в `on.push.branches`.
2. Устанавливает зависимости через `npm ci` и выполняет `npm run build`.
3. Публикует содержимое `dist/` в ветку `gh-pages`.

Проверка `check:anchors` пока не включена в workflow — запускайте её отдельно перед публикацией.

### Базовый путь и прямые ссылки

В `vite.config.js` задан `base: '/zc33s/'`, а React Router использует его как `basename`. Плагин сборки создаёт HTML-оболочки с SEO-метаданными для маршрутов из `spaRoutes` и файл `404.html`, чтобы поддерживать прямые переходы на GitHub Pages. Это не полноценный серверный рендеринг React.

При переносе сайта на другой домен или путь проверьте `base`, абсолютные URL в SEO-данных и `index.html`, а также адреса в плагине генерации HTML. Для ресурсов в коде используйте `import.meta.env.BASE_URL`, чтобы сохранить работу сайта в подкаталоге.
