# Руководство по ремонту Suzuki Swift для ZC33S

Подготовлено для Suzuki Swift Sport ZC33S. Источник — руководство AJPHSB0P / 42-52R20 («Swift комплексное издание»). На сайт переносятся главы 0–10 в исполнении, относящемся к ZC33S: двигатель K14C, передний привод, 6MT и 6AT, задние дисковые тормоза. Всего **2088 документов** в 11 главах и 72 разделах. Применимость ко всем годам выпуска не заявляется.

Не переносятся: полный привод (3B дифференциал, 3C раздаточная коробка, 3D карданный вал, ветки 4WD в 2C и «задний» в 3A), вариатор (5E), AGS (5D), 5MT, барабанные задние тормоза, система остановки холостого хода (10I), гибридные системы (11, 11A, 11B, 10K, обзор 11) и ветки других двигателей. Отдельные каталоги DTC/симптомов и PDF тоже не перенесены. Ссылки на такие материалы остаются в тексте и ведут на страницу «материал пока не перенесён».

В двух разделах комплектация ZC33S различается, поэтому публикуются обе ветки, и у каждого документа подписано его исполнение: 8B (SRS 4ch и 10ch) и 10A (обычный и адаптивный круиз-контроль, у комплектации Safety).

Первая проба (11 документов «Зажигание → K14C», раздел 1H) входит в этот объём и остаётся контрольным набором: проверка требует для неё 12 иллюстраций, 5 таблиц, 9 диагностических групп, 18 ответов и 18 действий.

## Повторный импорт

Требуются зависимости проекта и UnRAR (на Windows используется стандартный путь установки WinRAR; можно указать `--unrar`). Исходный RAR в репозитории не хранится.

```powershell
npm ci
npm run manual:import -- --archive "C:\path\RU V3 Руководство по ремонту Suzuki Swift для Firefox.rar"
npm run manual:test
npm run manual:check
npm run check:anchors
npm run build
```

Архив распаковывается один раз во временный каталог, который удаляется после импорта. Импорт занимает около полутора минут, почти всё время уходит на перекодирование схем в WebP (параллельно по числу ядер). Кодировка списка UnRAR на текущей Windows — OEM 866; на другой системе можно задать `UNRAR_LIST_ENCODING` (`utf-8`, `windows-1251`). XML читается в UTF-8. Архив передаётся явно; импортёр не ищет файлы в Downloads автоматически.

Данные готовятся во временном каталоге и полностью проверяются до замены `public/manual`. Если каталог нельзя переименовать (на Windows его блокирует запущенный `npm run dev`), импорт делает резервную копию и заменяет файлы по одному с откатом при ошибке. Сборка и проверки готовых файлов работают без RAR и UnRAR.

## Охват

Охват задаётся в `scripts/manual/pilot.mjs` (`MANUAL_SCOPE`): главы, их разделы (код файла `webdocstructure_XX.xml`) и ветки вариантов в каждом разделе. Раздел без указанных веток берётся из общей ветки `configtype none title`. Если нужной ветки нет или она встречается дважды, импорт останавливается. Порядок и группы документов берутся из исходного оглавления, названия и номера разделов — из `webdocstructure.xml`.

Ключ раздела — код файла (`18`, `F1`), потому что номера в исходнике повторяются: обзор главы «1» (`F1`) и меры предосторожности «1» (`10`). Номер из исходника (`1H`) показывается на сайте. Обзоры глав (`F0`–`FA`) публикуются в ветке «спорт», где она есть, и подписываются «обзор».

`SECTION_TITLES` заменяет на сайте явно неверные машинные названия разделов: «начиная» → «запуск», «схватить» → «сцепление», «лист» → «сиденья», «тело» → «кузов», «руль» (6B) → «рулевое управление», «обзор» (0A) → «введение». Исходное название сохраняется в `index.json` как `sourceTitle`. Названия глав заданы в охвате.

`SOURCE_FIXES` содержит точечные исправления исходного XML. Сейчас оно одно: неэкранированный «<» в тексте `AJPHSB0PF40I007`. Исправление применяется только при ровно одном совпадении и записывается в `report.json` (`sourceFixes`); хеш источника считается до исправления.

## Исправления перевода

Русский текст исходника — машинный перевод. `scripts/manual/wording.mjs` при импорте исправляет только частые однозначные ошибки, с явными падежными формами и сохранением заглавной буквы:

- «комбинированный счётчик» → «щиток приборов» (combination meter), «катушка IG» → «катушка зажигания», «скользящий штифт» → «направляющий палец» (суппорт), «датчик угла поворота кулачка» → «датчик положения распредвала», «2-кулачковый» → «DOHC»;
- «модуль накачки/надува/инфлятора» → «модуль подушки (шторки) безопасности», «система надувания» → «цепь срабатывания»;
- «экзамен по вождению» → «пробная поездка», «Осуществлять.» после ссылки на процедуру → «— выполните.», двойной знак вопроса «?？» в вопросах диагностики → «?»;
- заголовки таблиц DTC «Детали диагноза» и «Предполагаемое место дефекта»;
- «передача инфекции» → «трансмиссия», «тело земля» → «масса кузова», «двигатель стиральной машины» → «двигатель омывателя», «стеклоочиститель и шайба» → «стеклоочиститель и омыватель», «Играйте в педаль…» → «Свободный ход педали…»;
- ячейки таблиц и названия, состоящие только из одного слова (`WHOLE_TEXT_FIXES`): «тело» → «кузов», «приостановка» → «подвеска», «схватить» → «сцепление». В обычном тексте эти слова не трогаются («ваше тело или одежда»).

Названия разделов с ошибками машинного перевода заменены в `SECTION_TITLES` (`pilot.mjs`), исходное название остаётся в `sourceTitle`: «электрический двигатель» → «электрооборудование двигателя», «двигатель механический» → «механическая часть двигателя», «Информация о приборе/драйвере» → «приборы и информация для водителя», «Стеклоочиститель и шайба» → «стеклоочистители и омыватели», «краска/покрытие» → «лакокрасочное покрытие» и др.

Заголовки заменяются только целиком (`HEADING_FIXES`): «Удаление» → «Снятие», «Разложение» → «Разборка», «Инспекция» → «Проверка» и др., потому что в обычном тексте те же слова верны («удаление DTC»). Исправления применяются к тексту, заголовкам, названиям документов, групп и ссылок, поэтому поиск находит исправленные термины. Количества элементов, якоря и ссылки не меняются; `manual:check` сверяет их с исходным XML как прежде. Строчная первая буква заголовков исходника («принципиальная схема») выводится заглавной стилями.

## Данные

- `public/manual/index.json` — разделы, порядок материалов, группы, цели ссылок и подписи, добавляемые оригинальными шаблонами.
- `public/manual/search.json` — индекс заголовков и полного текста (~6,3 МБ, загружается только при первом поиске).
- `public/manual/documents/` — отдельные документы в виде дерева разрешённых узлов (~30 МБ на диске, загружаются по одному).
- `public/manual/images/` — иллюстрации опубликованных документов, перекодированные из JPG в WebP с качеством 80 (3546 файлов, ~156 МБ вместо ~307 МБ JPG). При двукратном увеличении мелкий текст схем визуально не отличается от исходного JPG.
- `public/manual/symbols/` — пиктограммы из `Xml/symbol` (момент затяжки, герметики, «одноразовая деталь» и т. п.), PNG без изменений.
- `public/manual/report.json` — SHA-256 источников (включая исходные JPG) и подготовленных файлов, количества элементов по каждому документу в исходном XML, ссылки и цели за пределами опубликованного объёма.

Исходные XML и шаблоны в `scripts/manual/fixtures/` служат для воспроизводимых проверок. Атрибуты и скрипты оригинального просмотрщика не исполняются. Неизвестный значимый элемент, неразрешённая ссылка, отсутствующая иллюстрация или пиктограмма останавливают импорт.

## Перенос оформления

`deflist` выводится, как в `suzuki.xsl`, таблицей «термин — определение». Пустые пометки правок `p-change` и `c-change` в XSL ничего не выводят и при импорте отбрасываются; если в такой пометке окажется текст, импорт остановится.

Подписи и пунктуация, которые добавляет оригинальный `suzuki.xsl` для русского языка, воспроизводятся явно: «ПРЕДУПРЕЖДЕНИЕ / ВНИМАНИЕ / ПРИМЕЧАНИЕ / УВЕДОМЛЕНИЕ», «Момент затяжки» и единица «Нм» после `t-value1`, маркеры `(a):` у `t-part1`, оформление материалов `m-part: m-desc m-number (m-name)`, сервисных данных `sdm-*`, нумерация `list2` (a.) и `list3` (i.). Диагностика `diag type="condition"` выводится таблицей «Условие / Возможная причина / Действие» с объединением ячеек по правилам XSL. Ссылки вида `AJPHSB0P1336003004` (ID подраздела без `#`) ведут к блоку того же документа и подписываются названием подраздела.

## Удобство чтения

- `/manual/` без параметра `doc` открывает обзор руководства: «Продолжить чтение» (последний открытый документ), быстрый доступ (регламент ТО, список запасных частей, аббревиатуры; списки кодов DTC и моментов затяжки по разделам) и все главы с разделами и числом материалов. На телефоне длинные списки DTC и моментов свёрнуты. В «хлебных крошках» документа первая ссылка ведёт на обзор.
- Поиск учитывает формы русских слов: окончание слова из запроса отбрасывается (основа не короче четырёх букв), поэтому «свечи» находит «свеча» и «свечей», «снятие» — «снять». Коды, числа и латиница ищутся как есть. Точная форма слова в заголовке поднимает материал выше, подсветка захватывает слово целиком.
- В текст поиска добавляются подписи блоков, которые показывает читатель («Момент затяжки», «Специальный инструмент»), поэтому «момент затяжки свечи» находит процедуру замены свечей.
- Поиск нормализует текст индекса один раз (повторный запрос — около 1 мс вместо 50–180 мс), показывает по 30 результатов с кнопкой «Показать ещё», подсвечивает совпадения и номер раздела. Клавиша «/» переводит фокус в поиск. На десктопе поле поиска закреплено вверху боковой панели.
- Оглавление «В этом документе» появляется, если в документе не меньше трёх озаглавленных разделов и тем (385 документов); ссылки ведут на якоря разделов.
- Закладки и «Недавно открытые» (8 последних) хранятся в `localStorage` этого браузера (`zc33s-manual-bookmarks`, `zc33s-manual-recent`). Если хранилище недоступно, списки работают до перезагрузки страницы.
- Боковая панель при открытии документа прокручивается к нему, не сдвигая страницу.
- Кнопка «Наверх» появляется после прокрутки на 1200 px.
- На телефоне оглавление открывается сразу на текущем документе, а схема открывается во весь экран.
- Значения моментов затяжки, материалов и сервисных данных выводятся одной строкой («свеча зажигания: 18 Нм»): переносы строк исходного XML по краям значений не показываются.
- Схема в окне просмотра: клавиши «+», «−», «0», Ctrl + колесо, перетаскивание мышью при увеличении; на сенсорных экранах прокрутка остаётся штатной.

## Проверки

- `manual:check` сверяет хеши всех файлов, совпадение индекса, поиска и отчёта, якоря, цели ссылок и для каждого документа количества иллюстраций, таблиц, диагностических групп, условий, причин, действий, предупреждений, ссылок, моментов, материалов и инструментов с исходным XML. Каждый раздел должен содержать документы, а ветка каждого документа должна быть среди опубликованных для его раздела.
- `manual:test` (37 тестов) включает реальные документы с таблицей условий, ссылками на подразделы, пиктограммами и материалами, выбор нескольких веток и обзоров без групп, `deflist`, исправления исходников, серверный рендер всех 2088 документов со сверкой количества иллюстраций, действий, причин, условий и терминов в HTML, а также оглавление по главам, закладки и недавние, подсветку и постраничную выдачу поиска, оглавление документа и хранение списков при недоступном `localStorage`, формы слов в поиске, подписи моментов затяжки в тексте поиска и обзор руководства (все разделы, списки DTC и моментов, ветки 8B).

## Результаты проверки 2026-10-28

- Импорт: 2088 документов в 72 разделах и 11 главах, 3546 иллюстраций (4096 вхождений), 121 пиктограмма, 233 цели ссылок за пределами опубликованного объёма, одно исправление исходника. Объём `public/manual` — около 200 МБ, из них 156 МБ схем; `index.json` — 0,8 МБ, `search.json` — 6,3 МБ (загружается только при поиске).
- Проходят 37 автоматических тестов, `manual:check`, `check:anchors`, `npm run build`.
- Визуально в headless Chrome на ширине 1440 px проверены: оглавление по главам, таблица аббревиатур (`AJPHSB0P0101003`), документ ветки SRS 10ch (`AJPHSB0P8220001`) с подписью исполнения. Проверки первой пробы (таблица условий, иллюстрации, пиктограммы, темы, 768 и 390 px) выполнялись на разделе двигателя.
- В Chrome (puppeteer) проверены: оглавление документа и переход по нему, «Наверх», закладка и «Недавно открытые» после перехода, «/» и выдача поиска с «Показать ещё», масштаб схемы клавишами и перетаскивание мышью, закрытие по Esc, раздел 10B на 390 px без горизонтальной прокрутки.
- В Chrome проверены обзор (1440 и 390 px, светлая и тёмная тема, сворачивание списков на телефоне, переход в документ и возврат через «хлебные крошки», «Продолжить чтение») и поиск по запросам «момент затяжки свечи», «замена колодок», «P0301».
- После исправлений перевода в Chrome проверены: момент затяжки одной строкой, DTC P0010 (таблица условий, схема, шаги «Да/Нет») на 1440, 768 и 390 px, окно схемы и оглавление на телефоне, печатный вид.
- Не проверялись вручную: копирование ссылки и все 2088 документов по отдельности.

Локальная проверка: `npm run dev -- --host 127.0.0.1`, затем `http://localhost:5173/zc33s/manual/`.
