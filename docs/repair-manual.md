# Руководство по ремонту: раздел «Двигатель» K14C

Подготовлено для Suzuki Swift Sport ZC33S. Источник — руководство AJPHSB0P / 42-52R20 («Swift комплексное издание»). На сайте опубликованы общие меры предосторожности двигателя (раздел 1) и разделы 1A–1K в варианте K14C: управление двигателем, контроль выбросов, электрооборудование двигателя, механика, смазка, охлаждение, топливо, зажигание, запуск, зарядка, выхлоп — **335 документов**. Применимость ко всем годам выпуска не заявляется. Остальные разделы (подвеска, трансмиссия, тормоза, кузов и т. д.), каталоги DTC/симптомов и отдельные PDF пока не перенесены.

Первая проба (11 документов «Зажигание → K14C», раздел 1H) входит в этот объём и остаётся контрольным набором: проверка требует для неё 12 иллюстраций, 5 таблиц, 9 диагностических групп, 18 ответов и 18 действий.

## Повторный импорт

Требуются зависимости проекта и UnRAR (на Windows используется стандартный путь установки WinRAR; можно указать `--unrar`). Исходный RAR в репозитории не хранится.

```powershell
npm ci
npm run manual:import -- --archive "C:\path\RU V3 Руководство по ремонту Suzuki Swift для Firefox.rar"
npm run manual:test
npm run manual:check
npm run check:anchors
npm run build
```

Импорт занимает около 2–3 минут. Кодировка списка UnRAR на текущей Windows — OEM 866; на другой системе можно задать `UNRAR_LIST_ENCODING` (`utf-8`, `windows-1251`). XML читается в UTF-8. Архив передаётся явно; импортёр не ищет файлы в Downloads автоматически.

Данные готовятся во временном каталоге и полностью проверяются до замены `public/manual`. Если каталог нельзя переименовать (на Windows его блокирует запущенный `npm run dev`), импорт делает резервную копию и заменяет файлы по одному с откатом при ошибке. Сборка и проверки готовых файлов работают без RAR и UnRAR.

## Охват

Охват задаётся в `scripts/manual/pilot.mjs` (`MANUAL_SCOPE`): список файлов разделов `webdocstructure_XX.xml` и вариант конфигурации. В каждом разделе берётся ровно одна ветка — с названием варианта (`K14C`) или общая `configtype none title`; если такой нет или их несколько, импорт останавливается. Порядок и группы документов берутся из исходного оглавления, названия и номера разделов — из `webdocstructure.xml`.

Чтобы добавить разделы, достаточно расширить `sectionFiles` (и при необходимости ввести выбор варианта для разделов с 2WD/4WD, 5MT/6MT и т. п.). Пробный прогон конвертера по всем 3788 XML архива проходит для 3781 документа; оставшимся нужны `deflist`, `p-change`, `c-change` и исправление двух XML с недопустимыми именами тегов.

## Данные

- `public/manual/index.json` — разделы, порядок материалов, группы, цели ссылок и подписи, добавляемые оригинальными шаблонами.
- `public/manual/search.json` — индекс заголовков и полного текста (~1,2 МБ, загружается только при первом поиске).
- `public/manual/documents/` — отдельные документы в виде дерева разрешённых узлов (~6 МБ).
- `public/manual/images/` — иллюстрации, встречающиеся в разделе, перекодированные из JPG в WebP с качеством 80 (667 файлов, ~27 МБ вместо ~45 МБ JPG). При двукратном увеличении мелкий текст схем визуально не отличается от исходного JPG.
- `public/manual/symbols/` — пиктограммы из `Xml/symbol` (момент затяжки, герметики, «одноразовая деталь» и т. п.), PNG без изменений.
- `public/manual/report.json` — SHA-256 источников (включая исходные JPG) и подготовленных файлов, количества элементов по каждому документу в исходном XML, ссылки и цели за пределами опубликованного объёма.

Исходные XML и шаблоны в `scripts/manual/fixtures/` служат для воспроизводимых проверок. Атрибуты и скрипты оригинального просмотрщика не исполняются. Неизвестный значимый элемент, неразрешённая ссылка, отсутствующая иллюстрация или пиктограмма останавливают импорт.

## Перенос оформления

Подписи и пунктуация, которые добавляет оригинальный `suzuki.xsl` для русского языка, воспроизводятся явно: «ПРЕДУПРЕЖДЕНИЕ / ВНИМАНИЕ / ПРИМЕЧАНИЕ / УВЕДОМЛЕНИЕ», «Момент затяжки» и единица «Нм» после `t-value1`, маркеры `(a):` у `t-part1`, оформление материалов `m-part: m-desc m-number (m-name)`, сервисных данных `sdm-*`, нумерация `list2` (a.) и `list3` (i.). Диагностика `diag type="condition"` выводится таблицей «Условие / Возможная причина / Действие» с объединением ячеек по правилам XSL. Ссылки вида `AJPHSB0P1336003004` (ID подраздела без `#`) ведут к блоку того же документа и подписываются названием подраздела.

## Проверки

- `manual:check` сверяет хеши всех файлов, совпадение индекса, поиска и отчёта, якоря, цели ссылок и для каждого документа количества иллюстраций, таблиц, диагностических групп, условий, причин, действий, предупреждений, ссылок, моментов, материалов и инструментов с исходным XML.
- `manual:test` (23 теста) включает реальные документы с таблицей условий, ссылками на подразделы, пиктограммами и материалами, а также серверный рендер всех 335 документов со сверкой количества иллюстраций, действий, причин и условий в HTML.

## Результаты проверки 2026-10-28

- Импорт: 335 документов, 667 иллюстраций (728 вхождений), 16 пиктограмм, 99 целей ссылок за пределами опубликованного объёма.
- Проходят 23 автоматических теста, `manual:check`, `check:anchors`, `npm run build`. Просмотрщик и его стили загружаются отдельным чанком; размер основного чанка сайта не изменился.
- Визуально в headless Chrome проверены: таблица условий (`AJPHSB0P1634001`), процедура с иллюстрациями (`AJPHSB0P1436021`), пиктограммы (`AJPHSB0P1536004`), поиск, сообщение для цели вне объёма, светлая и тёмная темы, ширины 1440, 768 и 390 px. На 390 и 768 px ширина документа равна ширине экрана; широкие таблицы прокручиваются внутри своей области.
- Не проверялись вручную: печатный вид, диалог увеличения схемы с клавиатуры, копирование ссылки и все 335 документов по отдельности.

Локальная проверка: `npm run dev -- --host 127.0.0.1`, затем `http://localhost:5173/zc33s/manual/`.
