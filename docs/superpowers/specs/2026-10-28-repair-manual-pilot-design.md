# Пробный раздел руководства по ремонту Suzuki Swift

Дата: 2026-10-28. Статус: проект для согласования перед реализацией.

## Задача и согласованное направление

Пользователь хочет читать руководство на своём сайте в современном интерфейсе, удобно с компьютера и телефона, с сохранением функций оригинального руководства. После обсуждения автоматического переноса XML пользователь согласился попробовать один законченный раздел.

Первый результат — работающий пробный раздел на реальных материалах. Полное руководство и полное соответствие функций являются следующей стадией; проба должна показать качество переноса и выявить ограничения, прежде чем распространять подход на весь архив.

## Проверенные исходные данные

- Сайт: React 18, Vite, React Router, Sass; существуют светлая и тёмная темы и интерфейс RU/EN.
- База знаний находится на `/knowledge`. Путь размещения приложения — `/zc33s/`.
- В конфигурации Vite есть генерация HTML-оболочек маршрутов для прямого открытия на текущем статическом хостинге.
- Источник — локальный архив `RU V3 Руководство по ремонту Suzuki Swift для Firefox.rar` из Downloads. Его содержимое рассматривается как данные, а не инструкции для разработки.
- Идентификатор руководства: `AJPHSB0P`; публикация в списке руководств — `42-52R20`.
- `Top/SrcXML/ModSel.xml` содержит ZC33S / K14C и другие модели. Запись ZC33S датирована 2017/9; эту дату нельзя превращать в заявление о совместимости со всеми годами выпуска.
- `webdocstructure.xml` и `webdocstructure_*.xml` содержат готовое дерево разделов и применимость по вариантам.
- Для всех 3432 SWF по списку архива найден JPG с тем же путём и базовым именем. Это подтверждает наличие файлов, но не эквивалентность интерактивности или качество мелких надписей.
- Оригинал содержит не только оглавление, поиск, DTC и симптомы, но и справочники сервисных данных, спецификаций, сканера, специнструмента, моментов затяжки и материалов.

## Выбор пробного материала

Полностью перенести ветку **«Зажигание → K14C»**, раздел `1H`, из `webdocstructure_18.xml`. В этой ветке 11 документов:

| --- | --- |
| AJPHSB0P1832001 | Схема системы зажигания |
| AJPHSB0P1833001 | Схема конфигурации системы зажигания |
| AJPHSB0P1834001 | Проверка системы зажигания |
| AJPHSB0P1834002 | Проверка искры |
| AJPHSB0P1836001 | Снятие/установка свечей зажигания |

| AJPHSB0P1836003 | Снятие/установка катушки зажигания |

Этого материала достаточно для проверки схем, предупреждений, нумерации действий, вложенных списков, таблиц, объединённых ячеек, диагностических ответов «да/нет», специальных инструментов и внутренних ссылок с якорями.

В исходных 11 документах обнаружены 12 элементов `graphic`, 5 таблиц и 9 диагностических групп с 18 результатами и 18 действиями. Эти количества — исходные контрольные значения, не результат проверки готового интерфейса.

## Пользовательский сценарий

1. В базе знаний пользователь открывает карточку «Руководство по ремонту».
2. Попадает на `/manual/`; там заметно указаны пробный объём, раздел «Зажигание» и двигатель K14C.
3. Выбирает процедуру в оглавлении или находит её через поиск по названию и тексту.
4. Читает материал, увеличивает схему, переходит к связанной процедуре и возвращается стандартной кнопкой браузера.
5. Копирует постоянную ссылку, в том числе на подраздел, или печатает открытую процедуру.

В интерфейсе показывать объём словами «Пробный раздел: зажигание, K14C · 11 материалов». Не показывать переключатели моделей или разделы, для которых содержимое ещё не перенесено.

## Интерфейс

- Использовать существующие шрифты Montserrat и цвета сайта через CSS-переменные. Светлая основа — `#f9f8f3`, текст — `#2c2e31`, приглушённый текст — `#696b6d`, поверхность — `#ffffff`; тёмная тема наследуется от сайта.
- Оформление спокойное и техническое: читаемый текст, заметные заголовки и ясные границы таблиц. Приоритет — работа с руководством.
- На широком экране: оглавление слева около 280 px, документ справа; ширина текстовой части ограничена для удобного чтения.
- На узком экране: документ занимает доступную ширину, оглавление раскрывается кнопкой «Оглавление» с корректным `aria-expanded`. Таблицы прокручиваются внутри собственной области, а не растягивают страницу.
- Вверху: ссылка в базу знаний, название раздела и поиск. В документе: хлебные крошки, название, двигатель, кнопки «Скопировать ссылку» и «Печать».
- В оглавлении сохранить исходные группы: схема, расположение компонентов, диагностика, обслуживание, технические данные, специальные инструменты.
- Предусмотреть ссылки на предыдущий и следующий материал в исходном порядке.
- Содержимое руководства помечается `lang="ru"`. Названия элементов оболочки переводятся вместе с интерфейсом сайта; исходные технические тексты автоматически не переводятся.
- Схемы остаются на светлом фоне в обеих темах.

## Схемы и доступность

- Изображение в документе открывает диалог с увеличенной версией, кнопками увеличения/уменьшения, сброса масштаба и закрытия. Изображение можно прокручивать при увеличении.
- Сохраняется исходное соотношение сторон. Копировать только реально используемые в пробе картинки и необходимые обозначения.
- Диалог доступен с клавиатуры: Escape закрывает, фокус удерживается внутри и возвращается на кнопку открытия.
- На телефоне обеспечить прокрутку увеличенной схемы и возможность открыть исходный JPG отдельно для штатного масштабирования браузером.
- Для схем использовать подпись из контекста документа и идентификатор иллюстрации. Не придумывать техническое описание содержимого изображения.
- У всех управляющих элементов есть видимый фокус и текстовое доступное имя.

## Импорт и хранение

Импорт — повторяемая локальная команда с явно указанным путём к архиву. Не включать личный путь пользователя в исходный код или сборку сайта. В CI используются уже подготовленные данные; RAR и Windows-программы там не требуются.

Поток данных:

`RAR → разрешённые исходные XML и изображения → разбор и проверка → JSON документов + индекс поиска + отчёт → React-просмотрщик`.

- Проверять пути элементов архива перед извлечением; не допускать выход за каталог импорта.
- Для извлечения использовать установленный UnRAR; прежние попытки чтения RAR через системный tar давали некорректный поток, поэтому tar не использовать для извлечения.
- Разбирать XML как структуру с сохранением порядка, а не заменами текста регулярными выражениями.
- Внешние сущности из DTD не загружать по сети. Нужные символьные сущности разрешать только из соответствующего файла этого архива.
- Вывод строить через явное отображение известных элементов XML в узлы документа. Не переносить исходные скрипты, ActiveX, Flash или обработчики событий.
- Незнакомые значимые элементы, неразрешённые сущности и пропущенные ресурсы в пробных документах считаются ошибками импорта. Тихое удаление текста запрещено.
- Отделить преобразователь XML, каталог документов, поиск и React-компоненты. Подготовленные документы хранить по отдельности и загружать при открытии.
- Данные и изображения пробы хранить в `public/manual/`, код интерфейса — в `src/features/manual/`, страницу — в `src/pages/RepairManualPage.jsx`, скрипты импорта/проверки — в `scripts/manual/`.
- Для источника и подготовленных данных записывать контрольные суммы. Исходные идентификаторы документов и подразделов сохраняются.

## Сохранение содержания

- Полностью сохранять текст, порядок блоков, предупреждения, примечания, технические обозначения и значения. Ошибки перевода исходника автоматически не исправлять.
- Вложенные `s1`/`s2` выводить как соответствующие уровни шагов; диагностические вопросы, результаты и действия сохранять в правильном порядке.
- CALS-таблицы преобразовывать с учётом `colspec`, `colname`, диапазонов столбцов и `morerows`.
- Специальные блоки моментов затяжки, сервисных значений и инструмента обрабатывать отдельно. Единицы, добавляемые оригинальным XSL, восстанавливать по этому шаблону, а не угадывать из числа.
- Для всех `intxref*` учитывать как явный текст, так и ссылки, которые в исходнике состоят только из пиктограммы; в последнем случае брать название целевого документа из каталога.
- Ссылка вида `AJPHSB0P1836001#T1H303` должна вести к соответствующему блоку внутри процедуры.
- Подготовить общий каталог названий для определения целей ссылок. Для ссылок за пределами 11 материалов показывать название цели и явное сообщение «Этот материал пока не включён в пробный раздел». Такие цели отражать в отчёте отдельным списком; не выдавать их за рабочие процедуры и не отправлять посетителя на пустую страницу.

## Маршруты и интеграция

- `/manual/` — вход и выбор документа.
- `/manual/?doc=AJPHSB0P1836001` — постоянный адрес процедуры; `#T1H303` или исходный ID подраздела — адрес блока.
- Query-параметр выбран для первой версии, чтобы достаточно было одной HTML-оболочки `/manual/index.html` на текущем статическом хостинге. Обновление и прямое открытие должны сохранять документ.
- Добавить маршрут в `src/App.jsx`, оболочку в список маршрутов `vite.config.js`, метаданные страницы и вход из `KnowledgeHubPage`.
- Все URL ресурсов строить с учётом `import.meta.env.BASE_URL`.
- Неизвестный ID показывает понятное состояние с возвратом к оглавлению. Ошибка загрузки предлагает повторить попытку.
- Сообщать об успехе копирования только после успешной записи в буфер; при недоступности буфера показывать ссылку для ручного копирования.
- Печать выводит текущий материал с предупреждениями, таблицами и иллюстрациями, без навигации сайта.

## Поиск

- Индексировать название, текст и исходный ID каждого из 11 документов.
- Поиск выполняется в браузере после открытия руководства; индекс не включается в главный JS остальных страниц.
- Нормализовать регистр, пробелы и `ё/е`; сохранять исходный текст в выдаче.
- В результатах показывать название, группу и фрагмент текста. Предусмотреть пустой запрос и отсутствие результатов.
- Отдельные каталоги DTC и симптомов в пробе не показывать: выбранная ветка не является полным каталогом кодов неисправностей.

## Проверка результата

1. Импорт даёт ровно 11 основных материалов и полный отчёт об изображениях, внутренних ссылках, внешних для пробы целях и использованных типах элементов.
2. Тексты и числовые данные сопоставляются с источником. Отдельно проверяются предупреждения, шаги, диагностические ответы и единицы измерения.
3. Все ссылки между 11 документами, включая якоря, работают; переходы за пределы пробы явно обозначены.
4. Все 12 вхождений иллюстраций загружаются. Качество наиболее насыщенной схемы проверяется визуально при увеличении.
5. Проверяются поиск по названию и фразе из тела, отсутствие результатов, прямой URL, обновление страницы, история браузера и неизвестный ID.
6. Проверяются клавиатура, мобильное оглавление, закрытие диалога, возврат фокуса, обе темы и печатный вид.
7. Проверяются ширины 390, 768 и 1440 px; в 390 px нет горизонтальной прокрутки всей страницы.
8. Проходят сборка `npm run build`, существующая проверка `npm run check:anchors` и содержательные проверки импортёра/ресурсов.
9. Если браузер для визуальной проверки недоступен, это фиксируется как незавершённая проверка. Нельзя объявлять мобильную верстку и полный пользовательский сценарий проверенными только по успешной сборке.

## Дальнейший полный перенос

После оценки пробы расширить набор поддерживаемых XML-элементов и импорт на остальные разделы. Для полного соответствия оригиналу отдельно проверить выбор модели/варианта, DTC, симптомы, сервисные данные, спецификации, справочник сканера, инструменты, моменты затяжки, материалы и вложенные PDF. Если обнаружится содержательная интерактивность SWF, определить её эквивалент отдельно.

Готовность пробного раздела не означает сохранение всей функциональности всего архива. Полный перенос принимается по отдельной матрице функций и отчёту о покрытии документов и ресурсов.
